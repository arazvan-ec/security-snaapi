## Solution for V1: JWT Authentication Pipeline (SPEC-F01 + F02 + F03 + F06)

### Class Design (from Shape A parts A1-A4)

```
src/Previum/
├── Authenticator/
│   └── PreviumJwtAuthenticator.php     # A2: AuthenticatorInterface
├── Model/
│   └── PreviumUser.php                 # Value object, UserInterface
├── Token/
│   ├── TokenValidatorInterface.php     # DIP abstraction for A3
│   ├── HttpTokenValidator.php          # A3: HTTP POST to auth microservice
│   ├── JwtDecoderInterface.php         # DIP abstraction for A4
│   └── FirebaseJwtDecoder.php          # A4: firebase/php-jwt

    ├── InvalidTokenException.php       # 401
    └── InsufficientPermissionsException.php  # 403
```

### SOLID Compliance

| Principle | How Addressed | Pattern |
|-----------|--------------|---------|
| **S** | Authenticator orchestrates only. Validation in TokenValidator. Decoding in JwtDecoder. | Extract Class |
| **O** | New user types = new authenticators. Validation strategy swappable. | Strategy |
| **L** | PreviumUser implements UserInterface fully | Interface Compliance |
| **I** | `TokenValidatorInterface::validate()` single method. `JwtDecoderInterface::decode()` single method. | ISP |
| **D** | Authenticator depends on abstractions (interfaces), not concrete HTTP client | DI |

## Solution for V2: Previum Editorial Endpoint (SPEC-F04)

### Class Design (from Shape A parts A5-A6)

```
src/Orchestrator/Chain/
└── PreviumEditorialOrchestrator.php    # A5: EditorialOrchestratorInterface
                                         # canOrchestrate() = 'previum'
                                         # execute() = no isVisible() check

src/Controller/V1/
└── PreviumEditorialController.php      # A6: thin controller
```

### Design Decision: Independent Orchestrator (D1 from shaped brief)

EditorialOrchestrator::execute() throws EditorialNotPublishedYetException at line 110-111. We can't compose/wrap because the exception fires before we can intercept. Independent orchestrator reuses same dependencies, skips the isVisible() check.

### SOLID Compliance

| Principle | How Addressed | Pattern |
|-----------|--------------|---------|
| **S** | Orchestrator aggregates previum data only | Chain of Responsibility |
| **O** | Added via `app.orchestrators` tag — ChainHandler NOT modified | Compiler Pass |
| **L** | Implements `EditorialOrchestratorInterface` fully | Interface |
| **D** | Same injected client interfaces as EditorialOrchestrator | Constructor Injection |
