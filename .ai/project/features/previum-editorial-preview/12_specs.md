# Functional Specs: previum-editorial-preview

> Phase 2 — WHAT the system must do (user/business perspective)

---

## SPEC-F01: JWT Token Extraction

**Description**: The system must extract a Bearer JWT token from the `Authorization` header of incoming requests to `/previum/{id}`.

**Acceptance Criteria**:
- [ ] Requests without `Authorization` header return `401 Unauthorized` with JSON error body
- [ ] Requests with malformed `Authorization` header (not `Bearer <token>`) return `401 Unauthorized`
- [ ] Requests with empty token return `401 Unauthorized`

**Verification**: Unit tests with mock requests missing/malformed headers

---

## SPEC-F02: JWT Validation via External Microservice

**Description**: The system must validate the extracted JWT by sending an HTTP request to an external authentication microservice. The microservice endpoint and configuration come from environment variables.

**Acceptance Criteria**:
- [ ] SNAAPI sends the client JWT to the auth microservice via HTTP POST
- [ ] If the auth microservice returns a non-2xx response, SNAAPI returns `401 Unauthorized`
- [ ] If the auth microservice is unreachable (timeout/network error), SNAAPI returns `401 Unauthorized`
- [ ] The auth microservice URL is configurable via environment variables

**Verification**: Unit tests with mocked HTTP client responses (success, error, timeout)

---

## SPEC-F03: User Type Verification from Response JWT

**Description**: The auth microservice returns a JWT in its response. The system must decode this response JWT and verify that the `user_type` claim equals `previum`.

**Acceptance Criteria**:
- [ ] Response JWT is decoded and `user_type` claim is extracted
- [ ] If `user_type === 'previum'`, authentication succeeds
- [ ] If `user_type !== 'previum'`, the system returns `403 Forbidden`
- [ ] If the response JWT is malformed or cannot be decoded, the system returns `401 Unauthorized`

**Verification**: Unit tests with crafted JWTs containing different `user_type` values

---

## SPEC-F04: Serve Unpublished Editorial Content

**Description**: Authenticated previum users can access editorial content regardless of publication status. The endpoint `GET /previum/{id}` returns the full editorial data, including editorials where `isVisible() === false`.

**Acceptance Criteria**:
- [ ] Published editorials are served normally (same data as `/editorials/{id}`)
- [ ] Unpublished editorials (`isVisible() === false`) are served instead of returning 404
- [ ] Non-existent editorials return `404 Not Found`
- [ ] Legacy-only editorials (no `sourceEditorial()`) are handled gracefully
- [ ] Response format is identical to `/editorials/{id}`

**Verification**: Integration tests with mock editorial client returning published/unpublished editorials

---

## SPEC-F05: Existing Endpoint Unaffected

**Description**: The existing endpoint `GET /editorials/{id}` must continue to work exactly as before, with no authentication required and no behavior changes.

**Acceptance Criteria**:
- [ ] `GET /editorials/{id}` requires no authentication (no `Authorization` header needed)
- [ ] `GET /editorials/{id}` still returns 404 for unpublished editorials
- [ ] No performance impact on the existing endpoint
- [ ] Existing tests continue to pass without modification

**Verification**: Run existing test suite; no test modifications needed

---

## SPEC-F06: Error Responses

**Description**: All error responses must follow a consistent JSON format compatible with the existing error handling in `ExceptionSubscriber`.

**Acceptance Criteria**:
- [ ] `401 Unauthorized`: `{"errors": ["Unauthorized"]}` (no token, invalid token, auth service failure)
- [ ] `403 Forbidden`: `{"errors": ["Forbidden: insufficient permissions"]}` (valid token but wrong user_type)
- [ ] `404 Not Found`: `{"errors": ["Editorial not published"]}` (editorial doesn't exist)
- [ ] Error responses do NOT include cache headers (private content)

**Verification**: Unit tests verifying exact response format and status codes
