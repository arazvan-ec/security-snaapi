## What We're Building

Un nuevo endpoint securizado `GET /previum/{editorialId}` que permite a usuarios con suscripción "previum" acceder a editoriales que **aún no están publicados** (preview de contenido).

### Authentication Flow

```
Cliente                    SNAAPI                     Auth Microservice
  │                          │                              │
  │  GET /previum/123        │                              │
  │  Authorization: Bearer X │                              │
  │─────────────────────────>│                              │
  │                          │  POST /validate (JWT X)      │
  │                          │─────────────────────────────>│
  │                          │                              │
  │                          │  200 OK + JWT Y              │
  │                          │  (contiene user_type=previum)│
  │                          │<─────────────────────────────│
  │                          │                              │
  │                          │  Decode JWT Y                │
  │                          │  Check user_type == previum  │
  │                          │                              │
  │  200 OK (editorial)      │                              │
  │<─────────────────────────│                              │
```

### Key Distinction from Existing Endpoint

| Aspecto | `GET /editorials/{id}` (existente) | `GET /previum/{id}` (nuevo) |
|---------|-----------------------------------|-----------------------------|
| Autenticación | Ninguna (público) | JWT obligatorio |
| Editoriales publicados | Sirve | Sirve |
| Editoriales NO publicados | Lanza `EditorialNotPublishedYetException` | Sirve (es su propósito) |
| Cache público | Sí (s-maxage) | No (privado, por usuario) |

## Why It's Needed

- Permitir previsualización de contenido editorial antes de su publicación
- Acceso restringido solo a usuarios premium ("previum")
- Validación delegada a microservicio externo (separación de responsabilidades)

## Who Benefits

- **Editores/Periodistas**: pueden previsualizar cómo se verá el contenido en la app
- **Usuarios premium**: acceso anticipado a contenido no publicado
- **Producto**: nueva funcionalidad de monetización

## Constraints

- **Technical**: Integración con Symfony Security (stateless), HTTP client para validación externa
- **Security**: Control Level = HIGH (primera feature de auth, código sensible)
- **Performance**: La validación HTTP añade latencia; considerar timeouts agresivos
- **Backward Compatibility**: El endpoint `/editorials/{id}` NO se modifica en absoluto

## Success Criteria

1. `GET /previum/{id}` sin token devuelve `401 Unauthorized`
2. `GET /previum/{id}` con token inválido devuelve `401 Unauthorized`
3. `GET /previum/{id}` con token válido pero `user_type !== 'previum'` devuelve `403 Forbidden`
4. `GET /previum/{id}` con token válido y `user_type === 'previum'` devuelve el editorial (publicado o no)
5. `GET /previum/{id}` con editorial inexistente devuelve `404 Not Found`
6. `GET /editorials/{id}` sigue funcionando exactamente igual (sin cambios)
7. Tests unitarios cubren todos los escenarios de autenticación
8. PHPStan level 9 pasa sin errores
9. Mutation testing mantiene MSI >= 86%
